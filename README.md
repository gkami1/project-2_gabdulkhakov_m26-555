# project-2_gabdulkhakov_m26-555

Консольное приложение на Python, имитирующее работу с базой данных.
Проект выполнен в рамках домашней работы по основам Python.

## Демонстрация

Полный цикл работы: создание таблицы, CRUD-операции, подтверждение удаления и удаление таблицы.

[![asciicast](https://asciinema.org/a/VgUwCm60LqrB0TrF.svg)](https://asciinema.org/a/VgUwCm60LqrB0TrF)

## Возможности

- Создание таблиц с типизированными столбцами (`int`, `str`, `bool`).
- Удаление таблиц и просмотр их списка.
- Автоматическое добавление столбца `ID:int` в начало каждой таблицы.
- CRUD-операции с записями: `insert`, `select`, `update`, `delete`.
- Фильтрация записей по условию `where`, вывод в виде таблицы (`prettytable`).
- Сохранение метаданных в `db_meta.json`, а данных каждой таблицы — в `data/<таблица>.json`.

## Управление таблицами

### Команды

| Команда | Описание |
|---|---|
| `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` | Создать таблицу |
| `list_tables` | Показать список всех таблиц |
| `drop_table <имя_таблицы>` | Удалить таблицу |
| `help` | Показать справку |
| `exit` | Выйти из программы |

Поддерживаемые типы данных: `int`, `str`, `bool`.

Столбец `ID:int` добавляется автоматически в начало каждой таблицы и не задаётся пользователем.

### Пример использования

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.

>>>Введите команду: list_tables
- users

>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Таблица "users" успешно удалена.

>>>Введите команду: drop_table products
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Ошибка: Таблица "products" не существует.

>>>Введите команду: exit
```

## CRUD-операции

### Команды

| Команда | Описание |
|---|---|
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | Создать запись |
| `select from <имя_таблицы>` | Прочитать все записи |
| `select from <имя_таблицы> where <столбец> = <значение>` | Прочитать записи по условию |
| `update <имя_таблицы> set <столбец1> = <новое_значение1> where <столбец_условия> = <значение_условия>` | Обновить запись |
| `delete from <имя_таблицы> where <столбец> = <значение>` | Удалить запись |
| `info <имя_таблицы>` | Вывести информацию о таблице |

Правила записи значений:

- строки указываются в кавычках: `"Sergei"`;
- логические значения — `true` / `false`;
- целые числа — без кавычек: `28`;
- значение `ID` не передаётся в `insert`, оно генерируется автоматически;
- все столбцы обязательны, типы значений проверяются по схеме таблицы;
- в `set` можно обновить несколько столбцов через запятую: `set age = 29, is_active = false`.

### Пример использования

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".
Функция insert выполнилась за 0.000 секунд.

>>>Введите команду: select from users where age = 28
Функция select выполнилась за 0.000 секунд.
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записи"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

## Обработка ошибок

Ошибки операций с базой данных обрабатываются централизованно декоратором `handle_db_errors` (модуль `decorators.py`). Функции из `core.py` не содержат `try...except`: при ошибке они выбрасывают исключение, а декоратор печатает сообщение и возвращает `None`, после чего программа продолжает работу.

| Исключение | Когда возникает | Пример сообщения |
|---|---|---|
| `KeyError` | Таблица или столбец не найдены | `Ошибка: Таблица "products" не существует.` |
| `ValueError` | Неверный тип, число значений, синтаксис команды | `Некорректное значение: x. Попробуйте снова.` |
| `FileNotFoundError` | Нет файла данных | `Ошибка: Файл данных не найден. Возможно, база данных не инициализирована.` |
| `Exception` | Любая другая ошибка | `Произошла непредвиденная ошибка: <описание>` |

Другие сообщения:

- неизвестная команда: `Функции <имя> нет. Попробуйте снова.`;
- пустой ввод — приглашение повторяется.

## Подтверждение действий

Опасные операции требуют подтверждения. Декоратор `confirm_action(action_name)` — фабрика декораторов: перед выполнением функции он спрашивает

```text
Вы уверены, что хотите выполнить "<действие>"? [y/n]:
```

и выполняет операцию только при ответе `y`, иначе печатает `Операция отменена.` и ничего не меняет.

| Команда | Действие в запросе |
|---|---|
| `drop_table` | `удаление таблицы` |
| `delete` | `удаление записи` |

## Замер времени выполнения

Декоратор `log_time` замеряет время выполнения функции через `time.monotonic()` и печатает его после вызова:

```text
Функция select выполнилась за 0.000 секунд.
```

Применяется к операциям `insert` и `select`.

## Кэширование

Функция `create_cacher()` возвращает функцию `cache_result(key, value_func)`, которая хранит словарь с результатами в замыкании. Если результат по ключу уже есть, он возвращается из кэша, иначе вызывается `value_func`, а результат сохраняется.

Кэш используется в `select`: ключ — имя таблицы и условие `where`, поэтому повторный одинаковый запрос не фильтрует данные заново. Кэш сбрасывается при любом изменении данных: `insert`, `update`, `delete` и `drop_table`.

## Хранение данных

Метаданные таблиц хранятся в файле `db_meta.json`, данные каждой таблицы — в файле `data/<имя_таблицы>.json`. Оба пути отсчитываются от директории, из которой запущена программа.

`db_meta.json`:

```json
{
  "users": {
    "columns": [
      ["ID", "int"],
      ["name", "str"],
      ["age", "int"],
      ["is_active", "bool"]
    ]
  }
}
```

`data/users.json`:

```json
[
  {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```
